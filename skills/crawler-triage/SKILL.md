# 接单分诊（crawler-triage）

## 第一步：需求解剖（从单子文本里抠出六要素）

平台 / 数据类型（评论、商家、商品、价格、公司）/ 具体字段清单 / 数据量（条数）/ 时效（一次性 or 持续更新）/ 交付格式（Excel 几乎是默认）。缺字段的先问清再报价。

## 红线判定表

| 单子特征 | 判定 |
|---|---|
| 商家经营信息（公司名/固话/地址/经营范围），登录后可见 | ✅ 低风险档，主力接。B 端获客刚需，属经营信息非个人信息 |
| 个体户/经营者的**个人**手机号批量列表 | ⚠️ 部分判例认定为公民个人信息。交付形态改为"公司名+固话+地址"，个人号码混入脱敏或剔除 |
| 消费者评论区：要内容不要评论人 | ✅ 接，交付时去身份字段（昵称/头像/用户ID不进表） |
| 消费者手机号/地址/实名 | ❌ 拒，没有商量 |
| 需要破解签名/越权接口才拿得到的数据 | ❌ 拒（"人看不见的"= 单子本身不该存在） |
| 数据只在 App 里有 | ⚠️ 走边缘试探协议（下节），试探失败转包或弃单 |
| 客户自带账号导自己店铺数据 | ✅ 最优单，零风险，优先抢 |

## 边缘试探协议（App 独占数据适用）

1. **抓包先行**（mitmproxy/Charles）：App 接口常比 Web 端裸（无签名或弱签名），抓包 30 分钟真相大白，落回"登录可见"就按普通单接
2. **JS 层签名限时试解**：仅 Web 端签名（x-s 之类），让 agent 静态分析 webpack 混淆代码，**限时 2 小时**，解不动就撤
3. **动态调试（Frida/unidbg）只做自用研究，不承诺交付**；签名周更，逆向产物是负债不是资产，除非单子溢价覆盖维护
4. 不行就算了——弃单成本远低于交付违约成本

## 武器矩阵

| 场景 | 武器 | 说明 |
|---|---|---|
| 电商 Web/h5（京东/淘宝/拼多多） | DrissionPage | 接管已登录 Chrome，见 scraper-blueprint |
| 商品/价格/部分评论 | 京东联盟/淘宝联盟/多多进宝 API | 合规通道，先查这里再动手爬 |
| 小红书/抖音 | MediaCrawler 系开源（Playwright+扫码） | 二次开发 |
| 商家信息（美团/点评） | DrissionPage + 店铺页遍历 | 注意地域翻页结构 |
| App 接口 | mitmproxy 抓包 → 还原参数 | 配合边缘试探协议 |
| 小批量（<500 条）人工核验类 | agent + dsh-browser 直接操作已登录浏览器 | 零代码，按小时计价 |

## 报价参考

报价 = 基础时薪 × 预估工时 × 难度系数 + 数据量系数。难度系数：联盟API可覆盖 1.0；DrissionPage 常规 1.5；需登录态+翻页深 2.0；App 抓包 2.5-3.0。数据量每上一个量级（千/万/十万）加一档。**持续更新单按月报**，别按次卖断。样本先行：先跑 20 条样本给客户确认字段再跑全量，防返工。

## 输出格式

```
【判定】接 / 拒 / 试探（试探附退出条件）
【风险档】低/中/高 + 一句话依据（对照上表）
【武器】具体方案 + 预估工时
【报价】区间 + 报价依据
【交付注意】脱敏要求 / 样本先行 / 验收口径
```
